# Fleetora — نسخة تجريبية على Railway

**الحالة:** نسخة عرض بقرار من المالك (D-030). **بيانات وهمية فقط.** ليست نظام الإنتاج: بيانات الشركة الحقيقية تبقى على خادم الشركة (D-012).

## الشروط التي لا تُتجاوز
1. بيانات وهمية فقط: لا أسماء أو هواتف زبائن حقيقيين، ولا CIN، ولا عقود أو صور حقيقية.
2. الدخول إجباري: كل بيانات التطبيق محمية، ولا يوجد تسجيل عام. فحص الصحة `/api/health…` وحده عام.
3. لا كلمات مرور حقيقية للشركة. كلمات المرور التجريبية عشوائية وطويلة (20 حرفاً).
4. قاعدة PostgreSQL خاصة: **لا تفعّل Public Networking ولا TCP Proxy لها**.
5. Railway Token لا يُرسل في أي محادثة؛ النشر من حاسوبك وبحسابك.

## البنية
- خدمة واحدة `Fleetora Demo App`: الخادم يقدّم الواجهة أيضاً (`WEB_DIST_DIR=../web/dist`).
- قاعدة واحدة `Fleetora Demo PostgreSQL`، خاصة.
- التعريف في `.railway/railway.ts` (حزمة `railway@3.16.0`، مثبتة في المشروع).

## تم التحقق منه محلياً قبل النشر (2026-11-02)
محاكاة بأوامر الملف نفسه وبـ `NODE_ENV=production`:
`npm ci --include=dev && npm run build` ناجح؛ الترحيلات (`preDeploy`) تعمل ومرة ثانية «up to date»؛
الواجهة تُفتح؛ كل واجهات البيانات ترد 401 دون دخول؛ لا يوجد مسار تسجيل عام؛ الكوكي
`__Host-fleetora_sid; HttpOnly; Secure; SameSite=Strict`؛ HSTS مفعّل؛ تسجيل الدخول من موقع آخر يُرفض (403).
**لم يُختبر بعد على Railway فعلياً** (لا يوجد ولوج إلى حسابك من هنا).

## خطوات النشر (من حاسوبك)
1. **من جذر المشروع، على الفرع `feat/slice-2a-fleet`:** تحقق أن `git status` لا يُظهر ملفات `.env` غير مستثناة.
2. **أنشئ في Railway** مشروعاً جديداً `Fleetora Demo` وبيئة `demo`. في Shared Variables للبيئة أضف `APP_ORIGINS=https://pending.invalid` مؤقتاً.
3. **اربط وراجع الخطة:**
   ```bash
   railway login
   railway link
   railway config plan
   ```
   يجب أن تضيف الخطة PostgreSQL والخدمة فقط. **إذا ظهر حذف أو استبدال لأي مورد: توقف.** ثم:
   ```bash
   railway config apply
   ```
4. **أنشئ النطاق العام للخدمة فقط** (Networking → Generate Domain)، ثم ضع الأصل الدقيق في `APP_ORIGINS`، مثلاً `https://xxxx.up.railway.app` (دون مسار ودون `/` في الآخر).
5. **ارفع النسخة المحلية دون GitHub:**
   ```bash
   railway up --service "Fleetora Demo App" --environment demo
   ```
6. **عبّئ بيانات العرض مرة واحدة**، من داخل الخدمة (لأن القاعدة خاصة ولا تُفتح للإنترنت). اسم القاعدة يظهر في متغيرات خدمة PostgreSQL (`PGDATABASE`، غالباً `railway`):
   ```bash
   railway ssh --service "Fleetora Demo App"
   FLEETORA_DEMO_SEED=fictitious-data-only FLEETORA_DEMO_DATABASE=railway npm run seed:demo -w server
   ```
   يطبع كلمات المرور **مرة واحدة**: احفظها في مدير كلمات المرور. إذا لم يتوفر `railway ssh` في نسختك من الأداة، استعمل نافذة الأوامر (Shell) للخدمة من لوحة Railway.
   السكربت يرفض العمل إذا: غاب العلم الصريح، أو اختلف اسم القاعدة، أو وُجد أي حساب، أو مُلئت إعدادات الشركة، أو وُجدت أي بيانات أعمال. لا يمكن تشغيله مرتين.

## الملفات المرفوعة (وثائق وصور السيارات) — مهم
قرص خدمة Railway يُمسح عند كل نشر جديد. لكي لا تضيع الصور والوثائق المرفوعة:
1. في خدمة `Fleetora Demo App`: **Settings → Volumes → Add Volume**، ومسار التركيب (Mount path) `/data`.
2. في متغيرات الخدمة أضف: `STORAGE_DIR=/data/files` (واختيارياً `MAX_UPLOAD_MB=10`).
3. أعد النشر. بدون هذا الـ Volume تعمل الرفوعات لكنها **تختفي بعد أي نشر**.
4. ارفع **ملفات وهمية فقط** (صور سيارات تجريبية، PDF تجريبي) — لا بطاقات رمادية أو تأمينات حقيقية.
