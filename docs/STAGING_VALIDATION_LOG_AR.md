# سجل تحقق Staging — Fleetora OCR

تاريخ: 2026-11-13

المشروع الجديد على Railway: `Fleetora OCR Staging`.
الرابط: https://fleetora-ocr-app-staging.up.railway.app/
قاعدة البيانات والـ Volume منفصلان عن الإنتاج.

## النتائج التي تم التحقق منها
- نجاح GitHub CI وفحص Docker للغات `ara` و`fra` و`eng` قبل أول نشر.
- نجاح بناء Docker الحقيقي داخل Railway، وتركيب Volumes واختبار اتصال Postgres.
- تطبيق ترحيلات قاعدة البيانات 0001–0014 بنجاح داخل قاعدة بيانات Staging مستقلة.
- نجحت اختبارات GitHub Actions الخارجية: صفحة البداية، /api/health، /api/health/db، /api/health/schema، رفض الوصول لواجهة الإدارة دون جلسة، رفض رمز دعوة مجهولة.
- نجح اختبار OCR محلي على صورة اصطناعية تحتوي رقم `AB1234567`، وتعرف Tesseract على النص. هذا لا يغني عن تجربة OCR داخل Staging ولا يعني ضمان دقة الوثائق الحقيقية.
- اختبرنا صورة اصطناعية ضبابية: انخفض مقياس حدة الصورة بصورة واضحة.
- لم يتم تغيير أي ملف أو قاعدة بيانات في تطبيق Railway الإنتاجي.

## نقاط المتابعة
- قبل اعتماد تجربة المستخدم، يجب إنشاء حساب مدير تجريبي والتحقق من نجاح الدخول.
- تنفيذ اختبار متكامل على حساب مدير وهمي: إنشاء وكالة/سيارة/زبون اصطناعي، إنشاء رابط ورمز، رفع الصور الاصطناعية، كشف الملف المكرر، التسليم للمراجعة.
- اختبار OCR بعد تفعيله على Staging فقط، والتحقق من عزل ملفات الهوية وصلاحيات المستخدم.
- إضافة قراءة اللوحة والعداد إلى واجهة السيارة، فالمحرك الحالي ما زال مرحلة Parser غير مرتبطة بالواجهة.
- تجربة كاميرا Android وiPhone وقياس جودة النتائج، واسترجاع Backup تجريبي قبل استعمال الإنتاج.

**لا ترسل وثائق أو صور هوية حقيقية أثناء اختبارات Staging.**
